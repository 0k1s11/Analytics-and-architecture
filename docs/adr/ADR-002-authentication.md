# ADR-002 — Authentication

**Статус:** Accepted  
**Источник:** разделы 4.1, 4.5, 4.10, 4.12.

## Решение

- Использовать готовые seed-аккаунты.
- Самостоятельная регистрация и сброс пароля не входят в MVP.
- Аутентификация API — Bearer Token.
- В БД хранится только стойкий хеш пароля: bcrypt, Argon2 или аналог.
- Секреты передаются через окружение и не коммитятся.
- `.env.example` не содержит реальных секретов.
- RBAC проверяется backend на каждом защищённом запросе.
- Роль определяется в контексте конкретного объекта.
- Дополнительно проверяются assignee и текущий статус.

## Порядок проверки

1. Авторизация.
2. Членство в объекте.
3. Роль `CUSTOMER` / `EXECUTOR`.
4. Дополнительное условие действия.
5. Текущий статус и допустимость операции.

Frontend может скрывать кнопки, но не обеспечивает безопасность.
