# 05 — UI Flows

Документ содержит экраны, URL, состояния UI, валидацию, API-вызовы и действия CUSTOMER/EXECUTOR.

### 4.8. Описать экраны и потоки

Вход под готовым аккаунтом

URL: /login

Экран доступен неавторизованным пользователям. Пользователь вводит email и пароль существующей учётной записи.

После отправки формы frontend выполняет запрос:

POST /api/auth/login

При успешном входе пользователь перенаправляется на /objects.

Состояния:

loading — кнопка входа блокируется, отображается загрузка;

error — выводится сообщение о неверном email, пароле или ошибке сервера;

empty и forbidden для данного экрана не применяются.

Валидация: email обязателен и должен иметь корректный формат, пароль обязателен.

Единый список объектов

URL: /objects

Экран доступен пользователям с ролью CUSTOMER или EXECUTOR.

Отображается единый список объектов, в котором у каждого объекта показывается название, адрес и бейдж текущей роли пользователя: CUSTOMER или EXECUTOR.

Пользователь может фильтровать объекты по своей роли.

Для получения списка используются:

GET /api/objects GET /api/objects?role=CUSTOMER GET /api/objects?role=EXECUTOR

Состояния:

loading — отображается загрузка списка;

empty — сообщение «У вас пока нет объектов»;

error — сообщение об ошибке загрузки;

forbidden — неавторизованный пользователь перенаправляется на /login.

Создание объекта

URL: /objects/new

Экран доступен авторизованному пользователю.

Пользователь заполняет название объекта, адрес, описание, плановую дату начала и окончания.

После отправки выполняется:

POST /api/objects

Создатель объекта автоматически получает роль CUSTOMER в созданном объекте.

Валидация: обязательные поля должны быть заполнены, дата окончания не может быть раньше даты начала.

Состояния:

loading — кнопка создания блокируется;

error — отображается ошибка создания объекта;

empty — отображается пустая форма;

forbidden — неавторизованный пользователь не может создать объект.

Добавление исполнителей

URL: /objects/{objectId}/members

Экран доступен только пользователю с ролью CUSTOMER в конкретном объекте.

Заказчик видит список участников объекта и может добавить исполнителя только из готовых учётных записей.

Для работы используются:

GET /api/objects/{objectId}/members

POST /api/objects/{objectId}/members

Повторное добавление одного и того же пользователя запрещено.

Состояния:

loading — загрузка списка участников;

empty — сообщение «Исполнители ещё не добавлены»;

error — ошибка загрузки или добавления;

forbidden — пользователь не является заказчиком данного объекта.

Карточка объекта

URL: /objects/{objectId}

Экран доступен заказчику и исполнителям, которые состоят в данном объекте.

На экране отображаются название, адрес и описание объекта, список карточек работ и финансовые агрегаты:

общая стоимость всех работ — total_cost;

сумма работ, ожидающих оплаты — awaiting_payment;

сумма оплаченных работ — paid.

Исполнитель может создать новую карточку работы. Заказчик может перейти к управлению участниками объекта.

Используются endpoint-ы:

GET /api/objects/{objectId}

GET /api/objects/{objectId}/work-items

Состояния:

loading — загрузка данных объекта;

empty — сообщение «В объекте пока нет карточек работ»;

error — объект не найден или произошла ошибка;

forbidden — пользователь не состоит в объекте.

Создание карточки работы

URL: /objects/{objectId}/work-items/new

Экран доступен только исполнителю, который состоит в объекте.

Исполнитель заполняет название работы, описание, стоимость и срок выполнения.

Создание выполняется через:

POST /api/objects/{objectId}/work-items

После создания карточка автоматически назначается на создавшего её исполнителя и получает статус PLANNED.

Валидация: все поля обязательны, стоимость не может быть меньше нуля, дата должна быть корректной.

Состояния:

loading — кнопка создания блокируется;

empty — отображается пустая форма;

error — ошибка создания карточки;

forbidden — пользователь не является исполнителем данного объекта.

Карточка работы

URL: /objects/{objectId}/work-items/{workItemId}

Экран доступен заказчику и исполнителям, состоящим в объекте.

На экране отображаются:

название и описание работы;

стоимость;

срок выполнения;

назначенный исполнитель;

текущий статус;

все подачи работы;

фотографии каждой подачи;

комментарии;

история изменения статусов.

Основные данные карточки загружаются через:

GET /api/work-items/{workItemId}

Комментарии:

POST /api/work-items/{id}/comments

История статусов:

GET /api/work-items/{id}/status-history

Доступные действия зависят от роли пользователя и текущего статуса работы.

Исполнитель может:

начать работу;

редактировать карточку только в статусе PLANNED;

отправить результат на проверку с 1–10 новыми фотографиями;

возобновить работу после возврата на доработку.

Заказчик может:

принять работу;

вернуть работу на доработку с обязательным комментарием;

отметить работу как оплаченную.

Для изменения статусов используются:

POST /api/work-items/{id}/start

POST /api/work-items/{id}/submissions

POST /api/work-items/{id}/rework

POST /api/work-items/{id}/resume

POST /api/work-items/{id}/accept

POST /api/work-items/{id}/pay

Состояния:

loading — загрузка карточки;

empty — отдельные блоки могут быть пустыми, например комментарии или история подач;

error — карточка не найдена или произошла ошибка загрузки;

forbidden — пользователь не состоит в объекте или не имеет прав на выполнение действия.

Frontend отображает только те кнопки, которые доступны текущей роли и статусу. Однако окончательная проверка прав, текущего статуса и бизнес-условий всегда выполняется на backend.
